# Playable narrative and character development

Use for story, quests, dialogue and characters in any 2D, 2.5D or 3D game. Read a relevant source with world_search_design_references and world_read_design_reference, then write an original game-specific structure. A reading list is not narrative implementation. [inkle's writing guide](https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md) is a useful reference for conditional choices, branching, recombination and persistent variables. The ink runtime is not bundled or automatically integrated.

Give an important character a current desire, obstacle, relationship to the player and an action they can take independently. Express these through scenes and interactions, not a biography the player never encounters. Establish an unresolved question early; let exploration or decisions change what the player knows and can do.

For an important choice define prerequisites, what is visible before choosing, the opportunity cost, immediate state changes and one delayed consequence. Two differently worded answers that always produce the same outcome are not automatically meaningful choice. A reconverging branch can still matter through changed trust, access, knowledge or resources. Preserve these differences in the save; never replay a resolved quest simply because it left the recent-context window.

Write compact canon and a current story state in ordinary design notes: stable IDs, resolved events, unresolved promises, character relationships and possible next developments. Generated follow-up content should respond to actual player actions and vary objectives, stakes or relationships. Do not force one prewritten plot regardless of player decisions. For dialogue-only scenes define how they affect exploration, resources, access, goals or interpretation; avoid endless exposition with no agency.

Implement state transitions, condition checks, presentation and save/reload in the game. Do not assume that importing an ink example or generating a paragraph creates those systems. Reuse licensed snippets only with their notices; external links in an example catalog have independent licenses. Write original names, dialogue and plot rather than copying a commercial game's story.

Verify two materially different branches, return to an earlier character, save and reload after a decision, and request a continuation that uses its consequences. Check dead/missing characters, unavailable clues, contradictory conditions, duplicate rewards and reachable endings or next arcs. For a finite game allow a deliberate ending; for an open-ended game allow resolution and a new tension instead of withholding every payoff forever. Record the observed branch and save values. Human response is needed to assess emotional impact; branch coverage alone does not prove good writing.
